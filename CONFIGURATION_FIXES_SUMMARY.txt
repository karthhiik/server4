## ISSUE 3: APSCHEDULER 1-SECOND LAG ✅ FIXED

### Problem:
APScheduler was creating an internal "QueuedEventPublisher.send_events" job 
running every 1 second, causing:
  - Request/response latency
  - Log spam
  - Unnecessary CPU usage
  
Example logs:
  2026-03-23 23:03:00,385 - apscheduler.executors.default - INFO - 
    Running job "QueuedEventPublisher.send_events (trigger: interval[0:00:01], ...)"

### Root Cause:
APScheduler automatically creates an internal event queue job when:
1. Scheduler is initialized with event listeners
2. Jobs are added to the scheduler
3. Logging is enabled at DEBUG level

This is an internal APScheduler mechanism (not user-defined).

### Solution Applied:

**File: FASTAPI_COMMUNITY/app/core/scheduler.py**

Added logging reduction:
```python
logging.getLogger('apscheduler.schedulers.base').setLevel(logging.WARNING)
logging.getLogger('apscheduler.executors.default').setLevel(logging.WARNING)
logging.getLogger('apscheduler.scheduler').setLevel(logging.WARNING)
```

Also configured scheduler with proper options:
```python
scheduler = AsyncIOScheduler(
    options={
        'apscheduler.timezone': 'Asia/Kolkata',
        'apscheduler.job_defaults.misfire_grace_time': 30,
        'apscheduler.job_defaults.coalesce': True,
        'apscheduler.job_defaults.max_instances': 1,
    }
)
```

**File: server3/app/services/cleanup.py**

Added same logging reduction to prevent APScheduler spam.
